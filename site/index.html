Does the new wp_kses() change your HTML?

WordPress runs the HTML in posts, comments, and a lot of plugins through wp_kses() to strip out anything unsafe. That function is getting a new parser, and some HTML will come out different. Paste yours below to see the before and after.

    What comes out different, and why
    
    
    The old wp_kses() was a chain of regular expressions guessing where the tags are. The new one parses HTML the way a browser does. These are the changes you're most likely to hit. Each output here is from WordPress 7.2-alpha-64255.
    
    
    
  
    

    


    
  
    
    
    
      
    Is wp_kses part of the HTML API?
    
      
    No. wp_kses() is a separate sanitizer. The new version is built on the HTML API's WP_HTML_Tag_Processor, which has been in core since 6.2.
    
    
    
    
    
      
    Need the old behavior back?
    
      
    add_filter( 'wp_kses_force_legacy_parser', '__return_true' ); switches back, but it's temporary. The legacy code could be gone in the same release this ships in, so use it to debug, not to ship.
